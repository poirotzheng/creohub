## 1. 生态定位

creo-hub 三层生态（docs\12）：**L1 封装**（本指南：把 PTK DLL 包成带清单的插件包）→ **L2 组合**（hub：注册表/状态机/reconcile/Web API）→ **L3 模型**（命令调用通道与 Agent）。

- **M2 交付**：L1+L2 管理面——装载/卸载/自动挂载/状态/日志/清单契约透出。
- **M2.5 交付**：MCP 桥底座（bridge\：管理工具面+hooks L1 闸门+preflight 自检）。
- **M3 交付（本指南现状）**：**命令执行面全量**——`/call` 执行链（A/B 双通道）+schema 硬校验+risk 三级闸门（nonce 确认链）+孤儿协议+依赖图调和+P1 版本化/回滚+P2 受控面台账+桥动态一级工具面+确认链代理（L1 hooks/L2 elicitation/L3 面板）。
- **M3.5 计划**：首客接入（test 相机视场插件）+`plugin_init` 脚手架。**M4 计划**：async 长任务/对话 tab/安装器/jlink 适配器。

## 2. 包结构（L1 封装产物）

```
<root>\plugins\<你的包目录>\
├── plugin.json                      ← 清单（必需，≤4MB，UTF-8）
├── bin\
│   └── <entry>.dll                  ← PTK 同步 DLL（必需，清单 entry 相对路径指向它）
└── text\                            ← textDir 指向这里（注意：Creo 会自动追加 \text！）
    └── text\usascii\
        └── <id>_messages.txt        ← 消息文件（菜单标签等）
```

- `<root>` = creo-hub 安装根（当前开发布局 `<REPO_ROOT>`；DLL 放 `build\out\` 或 `bin\` 均可被 root 探测识别）。
- 插件包**不需要**自己的 protk.dat —— hub 经 PTK 辅助应用 API 编程式装载（清洁装卸契约见 §9）。
- 新包放入 `plugins\` 后：面板/菜单 **Refresh Registry** 即被扫描收录（v2 清单变更同理）；但**新增包的菜单按钮**需 hub 重启（Aux Apps 停止/启动）才出现（面板按钮无此限制）。
- **版本化指针包变体（M3b b3，P1）**——需要热切换/回滚的包可用两层结构：

```
<root>\plugins\<你的包目录>\
├── plugin.json                      ← 薄指针：{manifestVersion, id, adapter, currentVersion:"<v>"}
└── versions\<v>\
    ├── plugin.json                  ← 生效全量清单（id 必须与指针一致，否则 INVALID）
    ├── bin\<entry>.dll
    └── text\text\usascii\...
```

  指针只重定向**一层**（versions\<v> 内不再认 currentVersion）；`POST /update`/`/rollback` = 切指针+排空级联重挂；手工改指针+refresh 同样有效。普通单层包行为不变。

## 3. plugin.json 公共字段（v1/v2 通用）

| 字段 | 类型 | 必需 | 约束（M3 实现） | 说明 |
|---|---|---|---|---|
| `manifestVersion` | number | **是** | ∈ {1,2} | 缺失或其它值 → INVALID |
| `id` | string | **是** | 1~63 字符，字符集 `[a-z0-9-]`，全注册表唯一 | 面板/状态文件/API 的主键 |
| `name` | string | 否 | ≤ 宽字符显示名 | 缺省显示 id |
| `version` | string | 否 | 显示用 | |
| `adapter` | string | **是** | 仅支持 `"ptk-sync"` | 其它值 → **UNSUPPORTED**（非 INVALID：包是好的，hub 还不会用） |
| `entry` | string | **是** | 相对路径，文件必须存在 | 指向 bin\<x>.dll |
| `textDir` | string | 否 | 若给出：其下必须有 `text\usascii` 子目录 | Creo 加载时自动追加 `\text`，故目录结构是 `textDir\text\usascii\` |
| `autoMount` | bool | 否 | 默认 false | 初值；运行期可被面板/菜单/API 改写并持久化到 `hub_state.json`（会话语义 S10） |
| `commands` | array | 否 | v1=对象数组仅取 `id`（§4）；v2=完整契约对象数组（§5） | v1 仅透出展示；v2 进入 /call 执行面 |
| `requires` / `provides` | array of string | 否 | **仅 v2**；各 ≤8 条，每条必须是字符串 | **M3b b3 起生效**：依赖图调和（拓扑挂载/排空级联卸载），不再是纯展示 |
| `currentVersion` | string | 否 | **指针包专用**（M3b b3）：1~31 字符 `[0-9A-Za-z.+-]`（b4 加固）；`versions\<v>\plugin.json` 必须存在且 id 与本包一致 | 指向生效版本目录（§2 变体） |
| `hubCmdExport` | string | 否 | 非空且 <64 字符 | 命令入口导出名（缺省 `hub_cmd`；不同则必须声明，mount 时前置校验该符号存在） |
| `callRoute` | string | 否 | `"B"`（direct，缺省）或 `"A"`（task） | /call 通道：B=进程内直调（E11 实证主选），A=ToolkitTask 信封（对照保留） |

## 4. v1 契约（冻结）

`manifestVersion:1`。字段如上表。v1 的 `commands` 为**对象数组**：每个元素必须有字符串 `id` 且带命名空间前缀 `"<插件id>."`（如 `demo.hello`），其余字段（`label` 等）宽容忽略、只存 id（至多 16 条）；字符串元素会被拒（`commands[%d].id missing`）。v1 对**未知顶层字段宽容忽略**（如 `userDisplay`、`host`）。v1 包在 M2 的解析、校验、状态机、挂载行为与 M1 **逐字节一致**——这是 DoD 11，由 O6 回归（39/39）永久看守。v1 清单**不做** v2 结构强校验（宽容读取哲学）。

**v1 包的 M3 语义**：无完整命令契约 → `/call` 一律 404（无执行面）；桥**静默跳过**、不产一级工具（demo/demo2/demofail/demoslot 等 v1 冻结基线包属此类——它们只有管理面与 Creo 菜单）。要上执行面，写 v2（§5+§14）。

## 5. v2 扩展（manifestVersion:2）

v2 = v1 全部字段 + **结构强校验**（R1：不过校验 → INVALID + 可读原因，绝不带病运行）：

### 5.1 commands[]（完整命令契约，G2 单一真源）

| 字段 | 类型 | 必需 | 约束 |
|---|---|---|---|
| `id` | string | **是** | 必须带命名空间前缀 `"<插件id>."`（如 `p-ok.hello`） |
| `title` | string | **是** | 人类可读短名 |
| `desc` | string | **是** | 人类可读说明 |
| `descForLLM` | string | **是** | **写给模型看**的操作说明（桥一级工具的 description 逐字直通；写清前置条件、参数含义、失败语义） |
| `risk` | string | **是** | 枚举 `safe` \| `confirm` \| `destructive`（**M3 执行闸门据此分级**，行为表=§8.4.3；面板三色徽章） |
| `inputSchema` | object | **是** | JSON Schema **允许子集**（§5.2；/call 前硬校验=422 指针级 details） |
| `timeoutSec` | number | 否 | 必须 >0（**M3 执行预算**=timeoutSec×1000ms；主线程同步不可抢占，声明要诚实且克制，建议 ≤5s，§16.6） |
| `reversible` | bool | 否 | 可逆声明必须诚实（铁律 4） |
| `idempotent` | bool | 否 | 幂等声明（**消费点**：504 超时的 `retryable` 字段=幂等才 true，§8.4.2） |
| `context` | string | 否 | 枚举 `part` \| `assembly` \| `any`，**缺省 any**（M3b b1 P-b1-1 最小惊讶：echo 类命令不应被零件窗约束） | 执行上下文声明。**仅声明+透出**（面板/桥/模型消费）；运行时解析由命令实现负责——用 `hub_sdk_active_part()`（§14.5），hub 不据此拦截 |
| `async` | bool | 否 | **M4b 新字段**：true=长任务，`/call` 立即返回 **202**+jobId，结果经 `GET /api/v1/jobs/<id>` 查询（§8.4.5）。`timeoutSec` 此时=ETA 提示（不是死线）；**不豁免 risk 闸门**；缺省 false=旧行为逐字节不变 |
| `undoCommand` | string | 否 | **M4b 新字段**：`"<插件id>.<命令>"`，同包内已存在的补偿命令（不得自引用）。`reversible:true` 时声明它=可逆性**机器可验**；hub 只在响应里给 `undo` 提示（`/call` 成功响应 `undo:{command,argsEcho}`），**绝不自动撤销**（P1b 手动精神） |
| `group` | string | 否 | **M4b 新字段**：命令分组（1~32 字符），manifest 透出+桥按组过滤一级工具（token 经济），缺省不填=misc |

- `commands` 数组本身可选；数组元素最多 16 个进入注册表槽位（cmdv[16]）。
- 每命令最多 16 条；requires/provides 各最多 8 条（超出 → INVALID 说明原因）。
- v2 的强校验范围 = `commands`/`requires`/`provides` 及其子结构（inputSchema 关键字白名单）；**未知顶层字段仍宽容忽略**（与 v1 一致，向前兼容新字段）。
- **导出前置校验（M3b b1）**：带 commands 的 v2 包 mount 成功后，hub 立即 `GetProcAddress(hubCmdExport)` 验证符号存在；失败 → 包**前置 INVALID+即时卸载**（面板明示 "Mount refused: hubCmdExport missing"），执行面绝不带病上线。v1 菜单包不受影响。

### 5.2 inputSchema 的允许子集（白名单校验）

- 顶层 `type` 必须是 `"object"`；
- 允许关键字：`type` / `properties` / `items`（**嵌套最多 1 层**）/ `required` / `description` / `enum` / `additionalProperties`；
- **未知关键字 → INVALID 并点名该关键字**（宁拒不放：执行前必须无歧义）；
- 序列化后 ≤ **1023 字节**（注册表槽位上限），超出 → INVALID。
- M3 消费点：`/call` 入队前 worker 线程**值域硬校验**（schema_val，7 关键字白名单与 registry 共享同一头文件=单一真源）；违规 → 422 `details:[{path,reason}]` 指针级自愈（真机实证：模型按 details 同回合改正重试成功）。**校验器自身故障/digest 失败 → 500 fail-closed（宁错杀）**；空 args 栈上对象无 fail-open（ISSUE-b1-1 修复实证）。

## 6. 状态机（7 态）

```
UNMOUNTED → INVALID            清单解析/校验失败（invalidReason 带原因）
UNMOUNTED → UNSUPPORTED        adapter 不认识（包是好的，hub 不会用）
UNMOUNTED → REGISTERED         清单有效，未装载
REGISTERED → MOUNTING          mount 请求，user_initialize 进行中
MOUNTING → ACTIVE              user_initialize 返回 PRO_TK_NO_ERROR（+b1：v2 命令包再过导出前置校验，失败→INVALID）
MOUNTING → ERROR               user_initialize 失败（非崩溃）
MOUNTING → TAINTED             ProToolkitDllUnload 失败（DLL 卡在会话里，需重启 Creo）
ACTIVE → UNMOUNTING            unmount 请求（b3：先排空级联——依赖它的 ACTIVE 包先传递性卸载）
UNMOUNTING → REGISTERED        user_terminate + DllUnload 成功
任意 → UNMOUNTED               rescan 时目录消失
```

- 状态持久化在 `hub_state.json`；崩溃重启后 `reconcile_from_disk()` 对账（§8.3）。
- **依赖图调和（M3b b3）**：mount-all/启动调和按 requires 拓扑排序（环检→成员 INVALID）；ACTIVE 包卸载=排空级联（`unmount dryRun:true` 可预览 drainedList）。**waitingFor 徽章仅限注册表中不可解析的依赖**（Q-M3b-2 裁定：依赖存在但未挂载=正常 REGISTERED，不出徽章）。
- **nonce 作废联动（M3b b2）**：包离开 ACTIVE 的一切转换点（进 UNMOUNTING/mount 失败 INVALID/TAINTED/ERROR/rescan 指纹变化）自动作废该包全部确认票据。

## 7. 清单指纹（R2）

`fnv1a64(生效 plugin.json 规范化字节)`，rescan 时比对：**指纹变化 → 卸载 + 重新收录**。持久化在 `hub_state.json` 的 `fingerprints` 表。用途：检测"同一 id 换了清单"这种最危险的静默漂移。

- **版本化双保险（M3b b3）**：指纹输入 = 生效清单 JSON + entry 文件**绝对路径**——防止"切了版本目录但清单字节恰好相同"的静默换版。
- refresh 对 ACTIVE 包**永远重算指纹**（b4 修复：指针已改、内存态未动的场景不再漏检）。
- 桥消费点（M3c）：`GET /health` 的 `manifestFingerprint` 是桥动态工具面的换代对账锚（启动拉取+调用随行探针+5s 轮询三路收敛；指纹变→原子换代→MCP list_changed）。

### 8.2 状态码语义（v1 冻结面；M3 全表=§8.4.2）

| 码 | 语义 | 响应形状 |
|---|---|---|
| 200 | 成功**或业务失败**（看 `ok`） | `{ok:true,...}` / `{ok:false,error:"<原因>",...}` |
| 400 | 请求体非 JSON / 缺字段 | `{ok:false,error:"invalid json body"}` 等 |
| 401 | 令牌缺失或错误 | `{ok:false,error:"unauthorized"}` |
| 404 | 路由不存在，或 id 不在注册表 | `{ok:false,error:"not found"}` / `{ok:false,error:"plugin not found",id:"..."}` |
| 409 | 状态冲突（如对 ACTIVE 包 mount） | `{ok:false,error:"conflict",...}` |
| 500 | hub 内部错误 | `{ok:false,error:"internal"}` |

### 8.3 执行模型（G1 信封，开发者需知的语义）

**单个信封 worker（严格串行）**：所有 POST 管理操作排入一条队列，由 PTK 定时器驱动的信封泵在主线程逐个执行，每步有超时（默认 10s，可用请求体 `timeoutMs` 覆盖，上限 30000）。**同一时刻只有一个管理操作在执行**，这是刻意设计——它让 hub 与 PTK 主线程的交互完全串行化，消除了一整类竞态。

**超时语义（v3 修订，M3b b2——分两类）**：

- **管理面动词**（mount/unmount/mount-all/unload-all/refresh/automount/update/rollback）：M2 语义不变——超时即放弃，响应 `{error:"timeout"}`（操作可能仍在后台跑，但**调用方已拿到超时判决**）；对状态改变型操作视为失败，用 `GET /plugins` 核实后重试；副作用永远不会在你的成功响应之后才发生。
- **op=call（POST /call）**：**报告不杀（report-don't-kill）孤儿协议**——执行预算=命令 `timeoutSec`×1000（未声明用缺省）；超时返回 `504 {error:"deadline exceeded", retryable:<幂等声明才 true>, meta:{timedOut:true}, timeoutMs, hint}`，但**不杀主线程**（PTK 同步调用不可抢占，杀=崩 Creo）。命令仍在跑 → **孤儿期**：`health.executorReady:false`+`orphaned:true`，期间新 `/call` → `503 {error:"hub busy-orphaned", retryAfterMs:1000}`（管理动词不受影响）；迟到完成落 `op=call.late` 审计行后**自动解除**。未执行即超时（如队列泵停摆）= `cancelledBeforeStart`，恒 `retryable:true`、不孤儿。**正确姿势=先查 `GET /health` 再决定，勿重试轰炸**（E11-8/M3c W4 真机三轮实证；信封泵对 Creo 模态对话框鲁棒——模态下 PTK 定时器仍驱动泵，M3b 微窗口定案）。

**崩溃恢复**：`hub_state.json` 持久化 AUTO_MOUNT 标志（不是运行时状态）。Creo 崩溃重启后，hub 用 `ProToolkitIsRunning()` 对每个 AUTO_MOUNT 包做**状态对账（reconcile）**：如果 Creo 报告 DLL 仍在运行（僵尸），hub 会把内存态直接恢复为 ACTIVE 而**不再调用 user_initialize**（否则会二次初始化 → 崩溃）。如果 Creo 报告不在运行，则走正常 mount 流程。这就是 `features` 里 `reconcile` 的含义。

#### 8.4.2 /call 状态码语义全表（docs\22 §6.1 冻结+b1/b2 真机终证）

| 码 | 形状 | 语义 |
|---|---|---|
| 200 成功 | `{ok:true, result:<命令 result JSON 原样>, ms, state:{model:"<模型名>", regen:<hub 变更计数>}}` | `state`=模型变更检测锚（业务命令自行填充 result） |
| 200 业务失败 | `{ok:false, err_code, err_msg, hint}` | **插件业务包线原样直通**——通道健康、业务失败；`hint` 写给模型自愈（422/biz-fail hint 均经真机自愈实证） |
| 400 | `{ok:false,error:"plugin and command are required"/"bad json"/"args must be a JSON object"...}` | 形状错 |
| 404 | `{ok:false,error:"plugin not found"/"command not found",...}` | **永不裸 miss**（带 error 字段与 hint） |
| 409 | `{ok:false,error:"plugin not active",state,hint:"mount the plugin first"}`；nonce 族：`NONCE_ARGS_MISMATCH`（三元组不符）/`NONCE_EXPIRED`（过期或不存在）/`NONCE_CONSUMED`（已烧，执行时点竞态）/`NONCE_PENDING_APPROVAL`（带票未批——先走 /confirm） | 状态冲突。**校验先于通道**（E11-6：卸载后 call→409 而非通道错） |
| 422 | `{ok:false,error:"schema validation failed",details:[{path:"args.<键>",reason:"..."}]}` | inputSchema 值域硬校验（指针级自愈） |
| 428 | `{ok:false,error:"confirmation required",needConfirm:{transactionId,nonce,risk,command,argsDigest,summary,expiresMs:60000,confirmVia:"panel-required"(仅 destructive)}}` | **前置条件缺失=需人类确认**（RFC 8658 语义）。`nonce` 全值仅令牌持有者可见，**永不入模型上下文**（桥 L2 进程内持有；L3 面板路根本不需要它——批准后裸重试自动配对） |
| 503 | `{error:"busy",retryAfterMs}`（单信封串行占用）/`{error:"hub busy-orphaned",retryAfterMs:1000,warning}`（孤儿期）/`{error:"confirmation table full"}`（16 槽全满，CSPRNG 失败 fail-closed 同此） | 暂时不可用，退避重试 |
| 504 | `{error:"deadline exceeded",retryable,meta:{timedOut:true,orphaned?:true},timeoutMs,hint}` | 报告不杀（§8.3 v3 修订） |

- **dryRun:true**：走完整校验链（令牌/形状/状态/schema/风险）但**永不入队**→ 200 `{ok:true,wouldExecute:{plugin,command,risk,needsConfirm,argsDigest}}`；需确认的命令**预发票据**（审计 `CONFIRM-ISSUE(dry)`；argsDigest 跨调用确定性真机实证）。
- **argsDigest** = FNV-1a64 规范化序列化（键序 qsort、数值叶规范打印 5≡5.0、NULL args≡{}）——批准与重试的**参数同一性锚**：三元组 (plugin,command,argsDigest) 不符 → 409 NONCE_ARGS_MISMATCH（C/JS 双面同规约，契约测试钉死；桥侧不复刻规范化，hub 为唯一权威）。

#### 8.4.3 风险闸门行为表（消费 commands[].risk 声明——铁律 4 诚实性的代价面）

| risk | /call 行为 | 桥/DSH 侧对应 |
|---|---|---|
| `safe` | 直接执行（hub 不拦） | L1 hooks 单层 ask 弹窗（DSH 审批面）；只读类工具豁免 |
| `confirm` | 无 nonce → **428 发票**；人工批准（Creo 面板 /confirm，或桥 L2 elicitation）后：**带 confirm_nonce 重试** 或 **裸重试**（批准后宽限窗内按三元组自动配对烧票=AUTOPAIR；M3e S1b：宽限=自批准起 10min） | L3 面板路（DSH 实况：桥不声明 elicitation 能力→428 投影"等待面板确认"→人在 Creo 面板批→同参重试） |
| `destructive` | 同 confirm，但 428 附 `confirmVia:"panel-required"` | **恒面板**（桥 L2 即使宿主支持表单也不提供会话内批准——最高风险级必须走到 Creo 面板前） |

- **nonce 生命周期**：ISSUED →(POST /confirm approve:true)→ APPROVED →(执行出队时**原子消费**)→ CONSUMED。消费点在出队而非入队（启示 11：排队中状态漂移→409 nonce-reject、**不烧票**）。**两段式 TTL（M3e S1b，2026-10-12 用户拍板）**：ISSUED=自签发 60s 注意力窗（实测 61s 拒绝；无人值守票卫生）；APPROVED=自批准起 **10min 宽限上限**（`NONCE_APPROVED_TTL_MS`）——修复"人工批准快、智能体重试回合慢"竞态（M3c W3 五票/M3d 六票编年史实证）；宽限到期→NONCE_EXPIRED 重发新票。16 槽；驱逐序 FREE→过期→最老 ISSUED→最老 CONSUMED（**永不回收活 APPROVED**；S1b 残余=已批准未消费槽最长占位 10min，表满=503 fail-safe）；纯内存，hub 重启即失效；已烧票在预检重放→428 重发新票（hint "previous nonce consumed"）。
- **作废联动**：包离开 ACTIVE（卸载/mount 失败/rescan 指纹变）→ 该包全部票据即时作废。
- **操作者模式（M3e Q1，2026-10-13 用户拍板+活体验证 docs\31 §1.3）**——上表是 **M0 标准**档行为；模式为**会话级全局开关**（纯内存、hub 重启回 M0、武装动作一律人手经面板模式条）：

  | 模式 | confirm 级 | destructive 级 | 审计 |
  |---|---|---|---|
  | M0 标准（默认） | 428 发票+面板批 | 428 发票+**恒面板** | CONFIRM-ISSUE/APPROVED 常规链 |
  | M1 会话信任 | **自动过票直通** | 仍 428 恒面板 | `CONFIRM-AUTOPASS mode=1`（每笔留痕） |
  | M2 限时无人（5/10/30min 窗） | 自动过票直通 | **自动过票直通** | `OPMODE-ARM mode=M2 … ack=1`（带全参）+`CONFIRM-AUTOPASS mode=2`；窗到期 `OPMODE-EXPIRE -> M0` |

  M2 武装**必须显式 `ack:true`**（面板=勾选"我知悉"复选框；服务端缺 ack/minutes∉{5,10,30}→400）。排队中被解除武装→执行时点消费失败→409 fail-closed。模式与 DSH 层审批正交（hub 闸门只减不加：DSH 该弹的照弹）。
- **插件作者定心语（M3e 自审补）**：操作者模式是**会话级操作者开关**，与包声明无关——您的 `risk`/`reversible`/`idempotent` 声明是闸门**唯一输入**；M1/M2 只改变"由谁批准"，不改变"您的代码该做什么"（safe/confirm/destructive 三条代码路径零差异，无需为模式写任何分支）。

#### 8.4.4 安全面（第 10 层，b4）

- **鉴权**：所有 `/api/v1/*`（**含读**）要求 `X-Hub-Token` 请求头 = `hub_token.txt` 内容（每次启动一次性随机令牌，不落日志；面板入口 URL 带 `?token=`，前端 JS 移入请求头并擦除地址栏，docs\11）。违规 → 401+`REJECT(unauthorized)` 审计。`/api/v1/opmode` 与 `/confirm` 同令牌同信任边界（M3e Q1：武装=操作者本人担险，面板 ack 勾选为唯一同意凭证，审计带全参）。
- **Origin 白名单（本机字面量，Q 裁定 2026-10-10）**：Origin 头缺失 → 放行（curl/node/桥/IE 面板均不发）；存在 → 必须逐字为 `http://127.0.0.1[:实际端口]` / `http://[::1][:端口]` / `http://localhost[:端口]`，否则 403；重复 Origin 头 → 400。
- **Host 校验**：非环回字面量 Host → 403（`REJECT Host`）；非环回 peer 地址 → 直接断连（`REJECT non-loopback peer`）。
- 以上 REJECT 族全部落审计（限频防刷屏）。

#### 8.4.5 async 长任务（M4b 加性面）

- **契约**：`commands[].async=true`（§5.1）。`/call` 校验链（令牌→schema→risk 闸门）照旧全走后，**入队成功即回 202**：
  `{ok:true, result:{jobId}, poll:{endpoint:"/api/v1/jobs/<id>", intervalMs:500}, meta:{async:true, etaMs}}`；业务拒绝仍走 4xx（不存在"已建 job 却被拒"）。
- **状态机**（命名对齐 MCP Tasks SEP-2663）：`queued → working → completed | failed`，排队期超时=`cancelled`（恒 retryable）。
- **查询面**：`GET /api/v1/jobs`（活任务；`?all=1` 含最近完成）与 `GET /api/v1/jobs/<id>`（`state/pct/msg/elapsedMs/result`，保留 **600s**）；**由 httpd worker 线程服务，不经主线程**——任务跑着也能查。
- **进度通道（v2 SDK）**：hub 每 job 建命名共享内存 `Local\creo_hub_job_<pid>_<n>`，名字经 `_ctx.progress_map` 注入；插件侧 `hub_sdk_progress(ctx,pct,msg)` 写入（单写者 seq 奇偶协议；无槽=no-op，绝不影响业务）。契约头=`sdk\hub_jobslot.h`。
- **诚实边界（铁律 4）**：async **不是并行**——任务执行期间 Creo 主线程仍被占，其他 PTK 命令排队/超时；`timeoutSec` 对 async 命令=ETA 提示（非死线）；**变更类 async 命令完成后不得盲重试**，先查 job/审计。
- **唯一语义差**：nonce 在主线程**出队时**原子消费（M3b 设计）；async 在 202 之后若出队消费失败（过期/被消费/args 漂移），无 HTTP 可回 → job 落 `failed` + `err_code=NONCE_*`，调用方经 /jobs 得知。
- **桥/面板**：`creo_hub_job` 工具（safe，轮询/列表）；面板顶部"任务"条只读展示进度（ES5 轮询）。health 加 `hubVersion` 与 `jobs:{running,queued}`（`executorReady:false` 时 jobs 仍可查）。

## 9. 清洁装卸契约 + 封装五铁律（v3 修订）

> **红线六条（违反=崩溃或闸门失效；细则见链出节）**：① `user_initialize` 内禁模态对话框（铁律 1，§16.1）；② `user_terminate` 返回前注销**全部** PTK 回调+登记簿自报（铁律 5/§9.1，E12 卸载后崩溃取证）；③ DLL 用 `/MT` 静态 CRT 编译（铁律 4）；④ risk/reversible/idempotent 声明诚实（铁律 4/§14.6——闸门与 504 retryable 直接消费）；⑤ `timeoutSec` 克制（主线程同步=整 hub 阻塞面，§16.6）；⑥ 文本资源走 `text\usascii`、不放中文路径（铁律 5/§16.2 `\text` 追加陷阱）。

PTK 的 DLL 装载机制（`ProToolkitDllLoad`/`ProToolkitDllUnload`）对插件有严格要求。**违反任何一条 = 卸载失败（DLL 永久卡住）或崩溃**：

1. **`user_initialize` 内禁止任何模态对话框**——`ProUIDialogShow` 是阻塞模态调用，必须改为异步 `ProUIDialogShowAsync`（demo 包 M2d 已修，实测卸载 15ms 清洁）。init 期模态会冻结装载流程且卸载时无法销毁（这是 demo_fail 包"init 弹窗卡死"教训的正式契约化）。
2. **`user_terminate` 必须销毁所有 UI 资源**——对话框、面板、自定义 UI 句柄全部释放。
3. **必须导出 `user_initialize`、`user_terminate`、`user_start`、`user_stop` 四个入口**——`user_start`/`user_stop` 可以为空函数。
4. **DLL 必须用 `/MT` 静态 CRT 编译**——`/MD` 会引入运行时依赖，卸载时可能因 CRT 状态不一致导致崩溃。build.cmd v3 已统一。
5. **`user_terminate` 返回前必须注销全部 PTK 回调**（v3 新增，E12 真机崩溃取证，§9.2）——ProUITimerRemove、通知监听、UI 回调、消息钩子一个不留。

### 9.1 E12 实证清理清单（v3 新增——契约级纪律，不是建议）

M3a E12 真机取证（docs\23 §9.2.3）：demoslot 在 `user_terminate` 故意遗留一个 ProUITimer 周期回调——卸载链路**全绿**（`ProToolkitDllUnload ret=0`、状态机干净落 REGISTERED、审计 NO_ERROR），**≈0.6 秒后（一个定时周期内）Creo 主线程 EXCEPTION_ACCESS_VIOLATION 崩溃**：UI 定时器派发跳入已卸载模块的代码段（traceback.log 栈顶 `GetLastError: 1114`）。

结论与纪律：

- **TAINTED 不兜此类缺口**——它只覆盖 FreeLibrary 拒释；回调炸弹在 hub 侧零内省手段，**检测不到**。防线只有一条：terminate 前注销一切。
- **SDK 自报登记簿（R2，M3b b2）**：每 arm 一个 PTK 回调就 `hub_sdk_arm(handle, "<kind>")`，释放时 `hub_sdk_disarm(handle)`；`user_terminate` 里调 `hub_sdk_terminate_check(report, sizeof report)`——armed>0 时报告走审计钩（`R2 terminate: DIRTY (n armed: kind,...)`），clean 时 `(0 armed callbacks)`。**登记是纪律义务**：hub 看不见你直接 arm 的回调（E12 教训），登记簿是唯一自证面。
- **P2 hub 侧台账（M3b b3）**：hub 在装载期登记它自己经手的受控面（命令导出/菜单按钮/nonce 槽/监听器四类），卸载时与插件自报对账。

### 9.2 五铁律（v3 措辞）

| # | 铁律 | 防的事故 |
|---|---|---|
| 1 | `user_initialize` 里不弹模态框（异步版可以） | init 卡死（demo_fail 实证） |
| 2 | 每个 DLL 至少带一条只读诊断命令（L0 起步即有） | Agent 接不进可观测面 |

## 10. 审计日志 Schema（R3，机器可解析；v3 兼容追加）

所有**状态改变操作**落一行固定格式（`hub_log` AUD 标签，INFO 级）：

```
[AUDIT] op=<verb> plugin=<id|-> args=<json|-> result=<text> ms=<n>
```

- `op` ∈ `mount` / `unmount` / `mount-all` / `unload-all` / `refresh` / `automount` / **`call`** / **`call.late`**（孤儿迟到完成）/ **`confirm_approve`** / **`confirm_deny`** / **`update`** / **`rollback`**（dev 构建另有 `_e11`）。REJECT 行 op 字段可为动词或 HTTP 方法（未授权/形状错在路由前拒绝时）。
- `args` = 请求体 JSON 单行（截断到日志行上限）。**敏感字段脱敏（M3b b2 ISSUE-L1）**：客户端带来的确认票据只落前 8 位掩码；**nonce 全值永不落日志**（仅 `nonce_id`=前 8 位作人侧关联 token）。
- `op=call` 行的 `result=` 文本形状（真机逐字）：`cmd=<命令id> risk=<safe|confirm|destructive> txn=<16hex|-> nonce_id=<8hex|-> result=ok|biz-fail ms=<n>`；`args=` 为完整 /call 请求 JSON。`op=confirm_approve` 行 `args=` 为 transactionId 16hex（非 JSON），`result=APPROVED`。**txn 贯穿 confirm_approve→call 两行 = 批准-执行配对可审计**（AUTOPAIR 链）。
- 审计行 INFO 级，默认落盘；`GET /api/v1/log?filter=AUDIT` 可程序化拉取。
- 日志轮转（R1，b4）：主日志达上限即改名为 `hub_m1.log.1`（**单代轮转**，旧 .1 被覆盖），审计不丢尾。

## 11. 面板如何呈现你的包（开发者速查；v3 四件套）

- **卡片标题行**：`[状态徽章] <id> <name> (version)` —— 徽章颜色：绿=ACTIVE、黄=MOUNTING/UNMOUNTING、红=ERROR/TAINTED、紫=INVALID、橙=UNSUPPORTED、灰=REGISTERED/UNMOUNTED。**INVALID/UNSUPPORTED 鼠标悬停显示 invalidReason**（你的校验失败原因会原文出现在这里，写清单时请让它可读）。
- **元信息行**：`adapter:<x> · entry:<path> · commands:<n> · req:<...> · prov:<...> · text:<path> · fingerprint:<16hex>` —— `entry`/`textDir` 是解析后的绝对路径，可用来核对 hub 实际看到的文件是不是你以为的那个。
- **v3 增量（M3b b4 四件套）**：①**确认抽屉**（M3e Q2 非模态化）——2s 轮询 /pending：**右上停靠抽屉**（overlay `pointer-events:none`，展开时面板其余功能照常可用；最小化/展开钮）；ISSUED 票=可操作卡片（批准/拒绝+60s 秒级倒计时，≤10s 红急样式），approved 票=**细状态条**（"宽限"分秒显示、无按钮）；无待批票自动收薄；destructive 红标 `panel-required`；**M3e S1b 语义**：服务端 remainingMs 按状态取窗为权威（ISSUED 60s / APPROVED 10min 宽限）；②**版本列/切换/回滚钮**——版本化包显示 currentVersion+可选版本；③**调和计划展示**——mount-all/排空级联前显示计划；④**孤儿红灯**——health.orphaned 联动（稳态跳过重绘防闪烁）；⑤**操作者模式条**（M3e Q1）——M0/M1/M2 选择+分钟档+ack 勾选+应用钮；M1 琥珀横幅/M2 红色横幅+剩余窗倒计时（health `opmode`/`opmodeRemainMs` 驱动；武装一律人手）。**R4 按钮使能联动**（状态驱动，ISSUE-C3 修复：服务端拒绝的操作不再画绿色"成功"行，行色=操作结果驱动）。
- **命令子表（v2 包）**：展开后每命令一行——`risk` 徽章（safe 绿/confirm 橙/destructive 红）、`desc`、`timeout:<n>s`、`context`、reversible/idempotent 图标。**descForLLM 不在面板显示**（那是给模型看的），但会在 `GET /manifest` 里原样返回。
- **autoMount 复选框**：勾选立即持久化到 `hub_state.json`，下次 Creo 启动生效；本次会话不自动挂载。
- **Refresh Registry**：重扫 `plugins\` 目录——你新放一个包进去，点这个按钮就能在面板看到（无需重启 Creo）。但**新包的 Creo 菜单按钮**需要 hub 重启（Aux Apps 停止/启动）才会出现，因为 PTK 菜单树在 DLL 装载期构建。
- 面板是 hub 内嵌的单一 HTML（docs\11），loopback-only+令牌鉴权；如果你的包需要自定义 UI，走 PTK 原生对话框（异步版），不要试图嵌入面板。

```c
/* 1) 命令函数：成功=返回 result JSON；失败=填 hint（+可改 ctx->err_code）、返回 NULL */
static cJSON* cmd_hello(const cJSON* args, HubCmdCtx* ctx, char* hint)
{
    const char* name = hub_sdk_str(args, "name");
    cJSON* r;
    if (!name) { ctx->err_code = "X_ARGS"; sprintf(hint, "name (string) required"); return NULL; }
    r = cJSON_CreateObject();
    cJSON_AddStringToObject(r, "greeting", name);
    return r;
}
/* 2) 分发表（末项 NULL 收口） */
static const HubCmdEntry G_CMDS[] = { { "x.hello", cmd_hello }, { NULL, NULL } };
/* 3) 一行导出（.def 里导出 hub_cmd；铁律 3） */
PRO_TK_DLL_EXPORT ProError hub_cmd(ProArgument* in, ProArgument** out)
{ return hub_sdk_entry(in, out, G_CMDS); }
```

### 14.1 API 面（**v2**，HUB_SDK_VERSION=2；对 v1/v0 源码完全兼容）

| API | 用途 |
|---|---|
| `hub_sdk_entry(in, out, table)` | ProTkdllFunction 兼容主入口（导出体一行转发到这里） |
| `HubCmdFn` / `HubCmdEntry` | 命令函数签名 `cJSON* fn(const cJSON* args, HubCmdCtx* ctx, char hint[256])` / 分发表项 |
| `HubCmdCtx` | `{sdk_version, timeout_budget_ms(hub _ctx 实填，0=旧 hub/未知), err_code(失败可改写，缺省 PLUGIN_ERROR), start_tick, progress_map(v2；NULL=同步命令/旧 hub), _progress_view(SDK 内部，勿碰)}` |
| `hub_sdk_str/num/bool(args,key[,dflt])` | 便捷取值（缺失/类型不符返回 NULL/缺省） |
| `hub_sdk_time_left_ms(ctx)` | **协作让路**：剩余预算毫秒（-1=无预算）。主线程同步不可抢占——长命令在安全点自查、归零前主动收尾返回部分结果或诚实失败（唯一正解，§16.6） |
| `hub_sdk_progress(ctx,pct,msg)` **v2** | **async 进度上报**：pct=0..100 或 -1（不确定）；msg=UTF-8 短消息（>191B 截断）；返回 1=已写入/0=无槽（no-op 安全，绝不影响业务）。仅对 `async:true` 命令有意义；进度可见≠并行（主线程仍被占） |
| `hub_sdk_set_audit(fn)` | 可选插件本地诊断钩（SDK 送短 ASCII 行：分发命中/业务失败码/耗时；**不落敏感内容**） |
| `hub_sdk_active_part(&err, hint)` | **统一零件上下文解析**（docs\24 §9 方案 1）：PART 窗直取 current；装配窗取激活组件（须为 PART）；无激活组件→`HUB_PART_NO_ACTIVE_COMP`+自愈 hint；非零件→`HUB_PART_NOT_PART`。成功返回 ProMdl（会话所有，勿释放） |
| `hub_sdk_arm/disarm/armed_count/terminate_check` | R2 回调登记簿（§9.1 纪律）：16 槽 `{handle,kind[24]}`；terminate_check 返回 armed 数并送审计钩 |

- **进度槽契约**（v2，跨模块）：`sdk\hub_jobslot.h`（hub 建 `Local\creo_hub_job_<pid>_<jobid>`，SDK 写、hub worker 读；单写者 seq 奇偶协议防撕裂）。长任务写法：
  ```c
  for (i = 0; i < n; i++) {
      if (hub_sdk_time_left_ms(ctx) == 0) { /* 诚实收尾：返回部分结果或失败 */ }
      do_step(i);
      hub_sdk_progress(ctx, (i + 1) * 100 / n, "step");
  }
  ```
- **版本策略**：v1→v2=加性（只增不破）；v1 插件源码不改可直接用 v2 头重编；不重编的 v1 插件在 v2 hub 下行为不变（hub 只多注入 `_ctx.progress_map` 一个 JSON 字段）。

### 14.2 双层错误纪律（SDK 内建，插件不可能写错层）

- **通道层**：`hub_cmd` 恒返 `PRO_TK_NO_ERROR`；唯一例外=输出根本无法分配（返 `PRO_TK_GENERAL_ERROR`，调用方能看到通道级失败）。
- **业务层**：成败一律走 OUT_JSON——`{ok:true,result:{…},ms:N}` 或 `{ok:false,err_code:"…",err_msg:"…",hint:"…"}`。
- /call 把业务包线**原样直通**给桥/模型（§8.4.2 200 业务失败行）；`hint` 质量=模型自愈率（真机实证：422 details 与 biz-fail hint 均驱动模型同回合自愈成功）。

### 14.3 载荷协议（E11 真机定案：char* UTF-8 主形态）

- `IN_JSON` = 一个 ProArgument，label `L"IN_JSON"`，值 STRING(char* UTF-8) 或 WSTRING(wchar_t*)——两种都收；文本 = `{"command":"<id>.<cmd>","args":{…},"_ctx":{"budget_ms":N}}`（_ctx=hub 注入预算，SDK 消费、命令函数不碰）。
- `OUT_JSON` = 一个 ProArgument，label `L"OUT_JSON"`，缺省 STRING(char* UTF-8)；编译期定义 `HUB_SDK_PAYLOAD_WCHAR` 切 WSTRING。
- 内存纪律（ProTkdllFunction 契约）：inputs 属调用方 SDK 不释放；outputs 由 SDK 经 ProArrayAlloc/ProValuedata*Set 分配，调用方 ProArgumentProarrayFree 释放。
- 载荷上限：RESULT/PAYLOAD_CAP 65536 字节（=httpd body cap，E11-4 64KB 实证）。

### 14.4 构建集成

- 编入插件 DLL 的源：你的 adapter/main + `hub_sdk.c` + `cJSON.c`；include 路径 +`sdk` +`src\hub\vendor\cjson`。
- 编译参数同 build.cmd v4：`/LD /O2 /W3 /MT /utf-8 /D_WINDOWS /D_WIN32_WINNT=0x0601 /DNTDDI_VERSION=0x06010000 /DNDEBUG /D_USRDLL /DUNICODE /D_UNICODE /DPRO_MACHINE=29 /DPRO_OS=4 /D_CRT_SECURE_NO_WARNINGS /DCJSON_HIDE_SYMBOLS`；链接 `protk_dll_NU.lib ucore.lib udata.lib`（+Win7 静态纪律：无 api-ms-win-*、子系统 6.00——`test\w7_check.cmd` 可自检你的 DLL）。
- `C4828` 编译警告无害（PTC 头 ProFeature.h 自带非 UTF-8 字符，/utf-8 下告警，不影响产物）。
- `.def` 导出：`user_initialize/user_terminate/user_start/user_stop/hub_cmd`（hubCmdExport 改名时以清单声明为准）。

### 14.5 接入阶梯（L0/L1/L2，docs\23 §6.1）

| 级 | 形态 | 得到什么 | 付出 |
|---|---|---|---|
| L0 | 纯 PTK DLL 零修改（v1 菜单包） | 管理面：装/卸/状态/审计/面板 | 无（但不进执行面） |
| **L1 标准封装（本指南主路径）** | +plugin.json v2 声明 +SDK 三样 | /call 执行面+一级工具面（模型可见可调）+风险闸门 | ~30 分钟（复制 demo3 改命令） |
| L2 hub-aware | 深用 budget/audit/active_part/登记簿 | 协作超时+上下文解析+卸载自证 | 按命令复杂度 |

### 14.6 风险分级写作指引（铁律 4 的操作化）

- **safe**=只读/无副作用/可任意重试（查询、回显、导出文件到临时区）。误报 safe 的代价=模型无人批准直通你的副作用。
- **confirm**=有模型侧副作用但可恢复/可预期（改参数、重生成、写文件到工作区）。
- **destructive**=几何/文件/状态的不可逆变更（删特征、覆盖保存、改注册表）。恒面板批准（§8.4.3），`reversible:false` 要如实。
- `timeoutSec`：主线程同步执行=**整 hub 阻塞面**（§16.6）——声明值≈P95 实测耗时+余量，超过 5s 的命令请重新设计（分步/协作让路）或等 M4 async。
- `idempotent:true` 才会在 504 时拿到 `retryable:true`——重试真安全才声明。
- `context`：命令摸模型就声明 `part`/`assembly`；纯逻辑命令留缺省 `any`。

## 15. 接入开源项目流程（v3 新增，docs\23 §6.2[4] 四步流水线）

把现有 Creo PTK 开源项目接入 creo-hub 生态的标准路径（**hub 不改开源项目源码语义**——L1 封装层原则：adapter 翻译、不侵入）：

1. **License 核查**：逐文件许可证扫描→分级：兼容（BSD/MIT/Apache/zlib/PTC 官方样例）/未知（联系作者或重写该文件）/不兼容（GPL 族→进程隔离方案或放弃）；结论入接入台账。
2. **L 级判定**（§14.5）：已有 DLL 导出四入口→L0 零修改先上管理面；要执行面→L1 加 v2 声明+SDK 三样（原项目的功能函数原样保留，adapter 只做 args→函数参数翻译）。
3. **脚手架**：M3.5 前=复制 `tools\plugin_tpl`（六模块骨架+抄改七步，§14.0b；或 demo3 工程三件套 def/adapter/main）+SDK 两文件+cJSON；M3.5 后=`tools\plugin_init` 交互生成。
4. **v2 声明+lint+真机微冒烟**：commands[] 完整契约→`node test\manifest_lint.mjs <包目录>` 离线全绿（INVALID 原因按 §5.3 逐条自愈）→真机：refresh→mount（弹窗）→safe 命令实调→审计行落账→（有 confirm/destructive 命令则走一遍面板批准链）→台账记录（谁/何时/license/L 级/冒烟结果）。

首客参照：一个真实的 Creo 相机视场插件（外部项目，M3.5 首客；接入前置=按本指南补 v2 声明）。

## 16. 常见坑与实证清单（v3 新增）

1. **init 模态框卡死**（§9 铁律 1，demo_fail 实证）：init 期 `ProUIDialogShow` 冻结装载流程且卸载时无法销毁。
2. **textDir 的 `\text` 追加陷阱**（§3）：目录结构必须是 `textDir\text\usascii\`——Creo 加载时自动追加 `\text`，少一层就资源加载失败。
3. **几何表转写类（M3d d1 新案例，ISSUE-L2）**：导入特征（ProIntfData）表驱动数据必须与官方样例**逐字 diff**——单面偏差**不报错**：Creo 静默丢面→开壳→`attempt_make_solid` 降级为面片，而 `created:true` 依旧诚实（特征确实建了，几何错了）。M3b P1/M3c M3C_LIVE 两次真机各见一次缺一面；M3d 修复=恢复样例 Surface-2 行（v3/origin/contour 三处转写偏差在同一行）+**制度化静态门** `test\run_p3_geom_check.cmd`（13 不变量族：右手系/共面/定向闭环/流形边/欧拉示性数/材料半空间/包围盒+自测模式"历史坏行必被抓"）。**教训：抄表就配门**（与 D5/D10 契约测试同一文化——双面钉死，防漂移）。
4. **C4828 编译警告无害**：PTC 头自带非 UTF-8 字符（/utf-8 下告警），不影响产物，不要为此改编译开关。
5. **httpd 单 accept worker（E10-5 实证）**：并发 HTTP 连接=串行处理（含 /call 与管理动词共泵）——压测/探测拿到的是队列语义不是并行；桥的 busy 退避（503 retryAfterMs）据此设计。
6. **主线程同步调用不可抢占（E11-8/§8.3）**：你的命令跑多久，整个 hub 信封泵就停多久（管理动词排队、新 /call 504/503）。诚实短小的 timeoutSec+`hub_sdk_time_left_ms` 协作让路是唯一正解；超时判决=报告不杀，别指望 hub 能"杀掉"你的调用。
7. **令牌与鉴权姿势（D-c4-5 实证）**：API 鉴权走 `X-Hub-Token` 请求头；脚本探活用该头（query `token=` 会被 401 拒——那是面板入口 URL 专用形态，由前端 JS 移入头）。
8. **卸载后回调炸弹（E12/§9.1）**：见五铁律第 5 条——TAINTED 不兜，登记簿自证。

## 17. 打包、安装与分发（M4 新增：T6/T7 工具链）

> 三个"打包"名词分工（docs\39 C8）：**plugin_pack**=单插件 zip；**release_pack**=发行包（M4c）；**install**=部署器。

### 17.1 打包单个插件：`plugin_pack`（零依赖、确定性）

```
node tools\plugin_pack\plugin_pack.mjs plugins\<id> [--out dist\packages] [--no-lint]
```

- 校验：plugin.json 可读 → lint（copy 流隔离根）→ 打包 → SHA256 → 索引；坏包 exit 1；
- 产物：`dist\packages\<id>-<version>.zip`（解压到 `<hub根>\plugins\` 即得 `plugins\<id>\`）+ `dist\packages\packages.json` 本地仓库索引（`{id,version,file,sha256,size,builtAt,requires,provides,files}`）；
- **确定性**：条目按路径排序 + 固定时间戳 → 同内容同 sha256（可复现审计）；STORE 无压缩（体积代价换零依赖）；
- 指针包（`currentVersion`）：整包打包（含 `versions\`），版本取指针值——升级后回滚仍可用；
- 气隙分发：构建机 pack → 拷 zip 到内网 → 解压到 `plugins\` → 面板 Refresh。索引文件可作"本地插件仓库"清单（谁、何版本、何 sha256）。

### 17.2 部署整机：`install.cmd` / `uninstall.cmd` / `doctor.cmd`（node 无关，Win7 可跑）

```
deploy\install.cmd   --root <hub根> [--creo-home <Creo用户配置目录>] [--src <载荷目录>] [--mode full|core] [--silent] [--yes]
deploy\uninstall.cmd --root <hub根> [--creo-home <...>] [--purge]
deploy\doctor.cmd    --root <hub根> [--creo-home <...>] [--mode full|core] [--deep]
```

- **install 做什么**：①预检（载荷/可写/creo-home 存在）②robocopy 落位（`build\out`+`web`+`hub_text`+`plugins`）③生成 `<root>\creo-hub.dat`（name/startup dll/exec_file/text_dir/description/fail_tol/allow_stop/revision/end）④在 config.pro 追加**标记块**（`# >>> creo-hub` / `toolkit_registry_file <root>\creo-hub.dat` / `# <<< creo-hub`）+ 首次写前备份 `config.pro.creo-hub-bak` ⑤验证 ⑥打印下一步；
- **幂等**：重复 install 先删旧标记块再写 → 永远只有一块；**可逆**：uninstall 按标记精确移除（不还原备份，防覆盖用户后续手改）；
- **不改的东西**：开发机 protk.dat/Creo 环境（本工具面向**部署机**）；不预先创建 `hub_token.txt`（hub 首次启动生成）；
- **注册机制（F2 已真机定案，2026-10-18）**：Creo 6 读 **启动目录**（快捷方式"起始位置"，常见 `C:\Users\Public\Documents`）的 `config.pro`；其中 **`PROTKDAT <root>\creo-hub.dat`** 指向独立 .dat 即可注册，`startup dll`（无 `delay_start`）**随启动自动运行**。安装器的 `--creo-home` 必须指向该启动目录（docs\39 §11.1 证据链）；
- **升级**：关 Creo → 备份旧 `build\out\creo_hub.dll` 为 `.bak-<ver>` → 覆盖 → 重启 Creo → `doctor`（比对 health.hubVersion）；失败=手动复制 `.bak` 回滚（P1b 手动回滚精神）；
- **doctor**：文件齐套/注册标记/备份/token/Creo 注册表/node（full 模式）/`--deep` 端口扫描 → `doctor_report.txt` + 退出码（FAIL→1，WARN 不失败）。

## 附：hub 自身的注册（protk.dat / ARegistry 核实结果，D3→M4 输入）

PTK 官方 `protkdoc\manual0\ARegistry.html`（本机 Creo 6.0.0.0 已核实）定义注册文件（protk.dat/creotk.dat）字段：`name`（应用唯一名）、`startup`（`spawn`|`dll`|`java`，默认 spawn）、`fail_tol`（TRUE=user_initialize 失败后 Creo 继续）、`exec_file`（DLL 全路径）、`text_dir`（文本目录，Creo 自动追加 /text）、`rbn_path`（ribbon 文件，默认 text_dir/toolkitribbonui.rbn）、`delay_start`（TRUE=不随启动加载）、`description`（Aux Apps 悬停帮助，≤80 字符）、`allow_stop`（TRUE=会话中可停止）、`end`。一个文件可含多个应用块。当前生产注册（`<CREO_STARTUP_DIR>\protk.dat`，M2 不变）：`name creo_hub / startup dll / exec_file ...\build\out\creo_hub.dll / text_dir ...\hub_text / allow_stop true / revision Creo6.0 / end`（`revision` 字段未见于 ARegistry 文档但实测可用）。**M4 一键安装含义**：安装器生成上述块即可（候选增强：`description`、`fail_tol true`）；Creo 对 .dat 的自动发现位置 ARegistry.html 未展开，M4 需实测（候选：loadpoint text 目录 / 用户手工注册一次）。
